# Fleet web access via Keenable vault

Create a **Keenable** connection in the Railway vault dashboard with a Keenable API key (`keen_...`) and exact base URL `https://api.keenable.ai`. Grant it to **each** fleet agent. The vault injects the key as `X-API-Key` server-side; each agent only needs its own `VAULT_TOKEN` and `VAULT_URL`, **not** `KEENABLE_API_KEY`. Optionally set `KEENABLE_VAULT_CONNECTION` to an exact connection ID when multiple Keenable connections are granted. The adapter discovers only ready, granted `keenable` connections with header auth and the exact API origin; the vault rechecks grants on every proxy request.

The bundled `web-vault-keenable` plugin registers `vault_keenable`. Set `web.backend: vault_keenable` (or `web.search_backend` and `web.extract_backend` separately) in fleet config, or leave backend selection automatic: a ready Keenable grant is preferred before Firecrawl and other configured providers. Explicit provider choices remain available. No direct provider key or official Keenable Hermes plugin belongs on agents: the official plugin reads the API key from the agent environment instead of using the vault.

The search adapter calls `POST /v1/search` with `mode: pro` and 1–10 results; extraction calls `GET /v1/fetch` with `live: true` and `max_chars: 50000`, at most five URLs sequentially. Both consume account credits. No automatic free/public-tier downgrade, browser rendering, anti-bot bypass, or stealth guarantee is implied. Secret-bearing/private URLs and website access policies are checked before requests and again on returned URLs. Auth, quota and rate errors are sanitized without upstream bodies.

Verify the vault's per-agent `/api/vault/list` shows a ready grant, then use ordinary `web_search` and `web_extract` with a public URL; vault audit records should show proxy calls to `/v1/search` and `/v1/fetch`. The catalog's one-result pro search probe may incur a credit. Railway does not have a Keenable key or connection by default: create and grant one explicitly, after receiving the key securely from the owner. Do not copy it into agent environments.

**Optional Firecrawl fallback:** Existing `web-vault-firecrawl` / `vault_firecrawl` remains supported. Create a Firecrawl vault connection with `https://api.firecrawl.dev`, grant it to agents, and optionally select it explicitly with `web.backend: vault_firecrawl` or disambiguate with `FIRECRAWL_VAULT_CONNECTION`. It uses `POST /v2/search` and `POST /v2/scrape` (rendered markdown) and consumes Firecrawl credits; it is not an anti-bot bypass guarantee. The Replit Firecrawl connector is not a Railway vault grant.
