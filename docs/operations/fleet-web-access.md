# Fleet web access via Firecrawl vault

Create a **Firecrawl** connection in the Railway vault dashboard with a Firecrawl API key, base URL `https://api.firecrawl.dev`, and grant it to **each** fleet agent. Each agent needs its own `VAULT_TOKEN` and `VAULT_URL` to reach the vault, not `FIRECRAWL_API_KEY`. Optionally set `FIRECRAWL_VAULT_CONNECTION` to the exact connection ID on an agent when more than one Firecrawl connection exists. The provider only discovers ready, granted bearer connections with service `firecrawl` or exact host `api.firecrawl.dev`; grants are checked again by the proxy.

The Replit Firecrawl connector (base `/v2`; `/scrape` tested) is **not** a Railway vault connection. Railway has neither direct Firecrawl provider keys nor Firecrawl vault connections by default: create and grant one explicitly. Do not copy the key into agent environments. The catalog probe is `GET /v2/team/credit-usage` (read-only); verify its availability with your Firecrawl plan/API version. A probe failure does not replace a real search/scrape test.

Bundled plugin `web-vault-firecrawl` registers `vault_firecrawl` automatically via `kind: backend`. Set `web.search_backend: vault_firecrawl` and `web.extract_backend: vault_firecrawl` (or shared `web.backend: vault_firecrawl`) in fleet agent config, or let the web dispatcher choose it as an available fallback. Check the vault's per-agent `/api/vault/list` for a ready grant and run a normal `web_search` and `web_extract` against a public URL; check vault audit records for proxy calls to `/v2/search` and `/v2/scrape`. No provider SDK or raw provider key is required on agents.

Search is limited to 1–10 results; extraction scrapes up to five URLs sequentially with rendered markdown. Search and scrape consume Firecrawl credits. URL secret, network, and website policy checks apply before sending and after receiving final URLs. Firecrawl's normal render can help with JavaScript sites, but **does not guarantee anti-bot bypass**; no paid stealth mode is enabled automatically.
